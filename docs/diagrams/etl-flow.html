Up to you — ETL pipeline

Six open-data sources, six DAGs, one content-addressed path — and a run ledger where a day that stored nothing is still a recorded day.

Content-addressed, not stamp-addressed

  • • A stamp can move while the data stands still, and stand still while the data moves. The hash of the bytes is the key.
  • • Where a file carries its own stamp too, the two are compared every run; a disagreement is exit 2 and it fails the task deliberately rather than guessing which signal to believe.
  • • Only the tax registry has two signals, so only its DAG can exit 2.

A no-change day is a recorded day

  • • Inferred from an absence, a broken source and a quiet one look identical — which is how a source stays broken for a week.
  • • So every attempt writes an ingest_run row, and no_change is an outcome rather than a missing row.
  • • invoked_by separates a scheduled run from a hand-triggered one; unset it and every DAG run claims to be cli, which is a wrong fact rather than a missing one.

The cheap half gates the expensive half

  • • Hash the 17 MB zip, claim the publication, and let the database answer whether the content is new.
  • • Only a returned id unzips the 99 MB CSV behind it. The file is monthly and the poll daily, so most runs stop at the claim.
  • • The tax registry keeps only rows whose 統編 is already in the latest reference publication: 14,521 of 1,711,012. The rest are never written — a storage decision, not an optimisation.
